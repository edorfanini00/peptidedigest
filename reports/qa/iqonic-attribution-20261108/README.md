# IQONIC calculator banner attribution

The existing banner on `/peptide-calculator` now sends a separately named
`iqonic_banner_click` to GA4 `G-QLTHZGWLMP` and offers the parent-authorized
AppsFlyer campaign link. A click is not an install or download.

Baseline: `314efdab6aa67f87d7217e96b34b71f52ad1c322`.

## Behavior and boundaries

- The server-rendered anchor points directly to the original App Store URL.
  Hydration selects the provider URL when no known refusal is present.
- GPC, DNT, GA opt-out and queued denials for analytics storage, ad storage,
  ad user data or ad personalization suppress both optional attribution paths.
  Explicit grants clear only their own purpose. Refusals are rechecked on
  focus, pointer down, context menu and activation.
- Pointer, keyboard and middle-click each emit one custom click event.
  Native navigation, modifiers, target and rel remain intact; no preventDefault,
  manual window opening, navigation callback or analytics wait is used.
- Missing analytics still permits the provider link. Throwing analytics or
  privacy access falls back to Apple. JavaScript disabled/blocked uses Apple.
- The event has an exact static payload, including a canonical page location,
  empty referrer and fixed title. No calculator values, query strings, click IDs
  or user identifiers are added. No new SDK, cookies or storage are introduced.
- Calculator code, banner copy/styles and shared shop tracking are unchanged.

## Provider provenance and limits

Exact authorized destination:

`https://app.appsflyer.com/id6765689488?pid=peptidedigest&c=calculator_banner&af_channel=web&af_ad=iqonic_banner`

Parent `PROVIDER.md`, supplied 2026-11-08, records the existing native AppsFlyer
integration for app 6765689488 and one iPhone-UA GET with distinct QA source and
campaign returning HTTP 301 to `https://apps.apple.com/US/app/id6765689488?mt=8`.
The builder read the current native integration without modifying it. No
production-campaign request or device install was generated by the builder.

[AppsFlyer's official link documentation](https://support.appsflyer.com/hc/en-us/articles/207447163-About-link-structure-and-parameters)
supports this single-platform route without a OneLink template. Attribution
depends on app first opens, SDK behavior and iOS privacy/reporting limits.
Dashboard campaign visibility and a real attributed first install remain
unverified. Parent should inspect IQONIC source `peptidedigest`, campaign
`calculator_banner`, distinguishing Installs from clicks. This is not proof of
all Apple downloads, purchases or trials. No native build was necessary.

## Verification

`npm ci` installed the lockfile without changing it. All of these passed:

```sh
npm run build
npm test                     # 87 tests
npm run typecheck
npm run lint
npm run start -- --hostname 127.0.0.1 --port 4873
BASE_URL=http://127.0.0.1:4873 npm run test:calculator:browser # 359 assertions
BASE_URL=http://127.0.0.1:4873 npm run test:iqonic:browser     # 91 assertions
git diff --check
```

Run browser commands in a separate terminal from the production server.
Chrome is the default; `BROWSER_CHANNEL` can select another installed channel.
The attribution suite fulfills external requests and adds an unavailable local
proxy as defense against Chrome modifier tabs bypassing Playwright routing.
Modifier navigation is compared against an untracked native reference anchor
under that same network guard. No provider request is made before activation.
The suite checks exact intercepted URLs, absent referrers, static GA payloads,
known refusals before/after hydration, script failures and the existing shop event.
It verifies client behavior, not Google ingestion or provider install reporting.

The initial pre-provider test uncovered that Chrome modifier tabs could escape
context routing and reach the ordinary Apple listing. The proxy guard was added
before testing the provider link; those earlier attempts did not use AppsFlyer.

The calculator suite verifies actual calculations, invalid states, keyboard
reset/tab order and sticky CTA hit tests at 360/390/430/1440px. All four banner
captures are pixel-identical to baseline; see `visual-comparison.json`.
Machine-readable results and final banner screenshots are in this directory.

## Existing concerns and release handoff

The baseline globally configures GA4 and Ads, with no consent interface or
privacy-state adapter found in the repository. This change does not repair that
sitewide behavior or strip identifiers the existing analytics library may add.
The custom payload and provider link are static; that is not a claim of anonymous
GA collection. `npm ci` reported 12 existing dependency vulnerabilities (8
moderate, 3 high, 1 critical); dependency upgrades are outside this feature.
Baseline build, lint and calculator browser tests passed.

Parent notes explicitly permit an automatic Vercel preview. No deployment
configuration, production deploy, merge, provider settings, credentials, Ads
goals/bids or native source were changed. Two independent reviews of the final
PR head and parent approval are required before any production release.

Rollback: revert this feature commit to restore the original plain Apple banner
link and remove its custom event. No migrations, configuration changes, native
release or data cleanup are required. Any rollback deployment remains parent-owned.
